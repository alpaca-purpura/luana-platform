## Mechanism

The kit has no Tailwind config of its own. Control atoms use `rounded-control`,
a utility class generated by each brand's `tailwind.config.ts::theme.extend.borderRadius.control`.

Chain:

```
brand globals.css  →  --radius-control: var(--radius)
                              ↓
brand tailwind.config.ts  →  borderRadius.control: "var(--radius-control, var(--radius))"
                              ↓
@luana/ui-kit atoms  →  className="... rounded-control ..."
```

Double fallback: CSS var fallback in Tailwind config + explicit token in globals.css.
Brands that skip globals.css still render at `var(--radius)` via the Tailwind fallback.

## Fix: md-exact control radius (commit `9574e31c`)

**Problem:** The original lift's proposal invariant was "cero cambio visual" for vitalia/comunify/lupulo,
but `--radius-control: var(--radius)` did NOT satisfy that invariant for vitalia and comunify:

- vitalia's old `rounded-md` = `calc(var(--radius) - 2px)` = `calc(0.625rem - 2px)` ≈ **8px**.
  The lift set `--radius-control: var(--radius)` = `0.625rem` = **10px** → **+2px regression**.
- comunify has no `borderRadius.md` override in tailwind.config.ts → old `rounded-md` used
  Tailwind v4 default (`--radius-md: 0.375rem` = **6px**).
  The lift set `--radius-control: var(--radius)` = `0.75rem` = **12px** → **+6px regression**.
- lupulo: `--radius: 0.375rem` = Tailwind default `rounded-md` → already correct, no change.
