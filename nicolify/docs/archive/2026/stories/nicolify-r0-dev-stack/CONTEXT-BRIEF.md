5. **Scenario 5 — `auth-vertical-slice`** (integration_point, corazón DONE): signin Clerk → root renderiza autenticado → fetchClient inyecta X-Tenant-ID (de Clerk publicMetadata) + Bearer JWT → BE valida vía `luana-core-iam` CLERK_ISSUER → 200. GET `/api/v1/iam/users/me` retorna User correcto.

7. **Scenario 7 — `fe-network-failure`** (network_failure): Root autenticado + BE 500 → manejo graceful (sin white-screen), mensaje español tuteo, loguea error.

One decision point flagged to PM (legacy snapshot — Chris confirmed delete recommendation). Everything else has a clear "consume" or "extend" verdict.

3. **The binding constraint is Chris-external.** Scenarios 2/5/6/7 (auth flows) are gated on Clerk dev instance + keys + seed. Scenarios 1/3 (stack health + migration idempotency) run standalone. Builders should document this dependency clearly in impl-log so auditor doesn't mark "E2E GREEN" impossible (it's not — it's "pending Chris key setup").

4. **Gherkin is unusually concrete.** 7 scenarios all have clear RED-first tests. The creation_order in 04-validators is 11 steps, each explicitly "RED before impl." This smells like a team that learned from a prior mistake (maybe Vitalia's "green after the fact" audit friction).

5. **Two gotchas to watch:**
   - **Legacy `001_initial_snapshot.py` is still in the worktree.** Architect says delete, but the file wasn't deleted pre-handoff. T-2 builder will hit this the moment they try to migrate. Make sure they read AD-3 carefully.

Builders will need to verify the allowlist matches story scope (3 routes only: `/`, `/sign-in`, `/sign-up` — no clinic/test-stack/webhook cruft).

6. **Assignment is all Sonnet.** No Opus, no agentic. Story is infrastructure/auth, not business logic. Cost estimate $1.95 for ~155 min of work across 5 tickets is realistic (builders are shipping bootstrap code, not inventing).

7. **Playwright freshness gate is the wildcard.** The `clerk.setup.ts` port includes a 4-hour TTL on the `storageState` file. If Chris creates the Clerk instance and walks away for 12 hours before builders run E2E, the token dies and retry kicks in. Not a blocker, just a real-world timing dependency to document.
